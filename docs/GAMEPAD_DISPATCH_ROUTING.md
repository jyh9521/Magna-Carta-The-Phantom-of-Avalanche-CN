# 手柄导航：按实际分发结果提交输入状态

## Verified：受控失败与原生顺序

旧导航函数进入即写`consumed=serial`，随后才检查GUI、标题阶段和焦点目标；
连按计时也在这些检查前推进。合法但不接收输入的根节点因而会让同帧后续
活动界面丢失方向输入。原始代码的新回归实际失败：
`FAIL inactive root must not consume same-frame direction intended for active menu`。

REA重新读取支持版本MCAlpha.dll的55134、565d2、567ed、4d3a0，
SHA256 `5c701de93af6267b959c49e6927bee525bc0f3c68c8c6f51413515d13809d427`，
Evidence `ev_157d116052ecd271a7da32655d4da26c6b9c57066014e4ece83ac9129df751d9`。
55134先分发子GUI，再检查自身资格；子节点或自身消费时返回1，否则返回0。
+160与+e8两个基础资格字段仅检查当前对象，不自动抹掉子节点资格。
旧收集器在遍历前拒绝非活动父节点，与该原生顺序不一致。
修正序号后的中间版本仍实际失败：
`FAIL inactive parent must retain active descendant navigation like native child-first dispatcher`。

## 修正

- 无效、非活动或没有可导航目标的根节点不提前提交序号或连按时间。
  成功移动焦点才提交，仍保留原350ms初始延迟与100ms后续间隔。
- 原始分发返回1时记录本次输入已消费，避免键盘专用界面虽然没有可收集
  矩形，却被另一个根节点抢走同帧方向输入。
- 原生方向消费者由原分发返回值决定消费，不仅凭“有自定义方向方法”就
  写序号。返回0的受阻原生控件仍允许后续界面处理该帧。
- 收集器先遍历子节点，之后才过滤父节点自身；父节点不活动时，子节点的
  独立资格仍保留。未知类、遍历数量、矩形、模态和源槽守卫不变。
- 原分发调用、返回值、SEH深度恢复、动作逻辑与键盘数据均保留。

32项UI夹具通过，覆盖非活动根→活动根的同序号路由、连按计时不提前推进、
成功后同序号只移动一次、非活动父与活动后代、原生消费/拒绝及原生方向拒绝。
源形状控件通过实际安装后的分发槽测试；受控原分发桩用0/1回放消费语义，
并保留旧7哨兵返回值检查。不是商业GUI执行或游戏内截图。
独立源回滚恢复20项原行为。51项输入/移动、IAT守卫和229项动作夹具继续通过。
