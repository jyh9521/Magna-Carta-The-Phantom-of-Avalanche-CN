# 八角色普通攻击、F10/F11伤害显示链

## 已验证：画外目标的数字子节点仍然绘制

2026-10-25，继续执行技能脚本、战斗模型命中帧和原生镜头后，发现第三个独立显示缺陷。
`AA2D1` 在即时锚点为 `(-1,-1)` 时只对弹字对象调用 `Hide(-1)`。
数值图形 `popup+F4` 及其数字子节点另挂在战斗GUI下，未跟随隐藏。
只隐藏数值父控件也不足：数字子节点有各自的绘制标记。

角色3、普通攻击14、EFS192、两个敌人的源指令回放，在第11逻辑帧中：
目标7的107伤害位于画外，目标72的47伤害位于画内。
修正前仍提交5个数字，正确数量应为2；另3位是画外目标的残留数字。
这证明技能镜头下的独立缺陷，不把受控场景认作玩家截图现场采样。

`damage_projection.cpp` 新增伤害弹字类虚表 `C19B0+28=C19D8` 的四字节守卫替换，
保留原生Hide，再同步数值控件及其最多16个数字子节点。显示恢复时同样同步Show，
不改伤害值、原生浮动、数字资源或生命周期，不隐藏另一目标的数字。
原12处CALL及新虚表项作为同一安装事务核对、失败撤回；指针按实际模块基址核对。
新就绪标记为 `revision=numeric_visibility_v3 digit_visibility=popup_state`。

独立原始源码构建重现5/2差异；新源码只提交2位，回切后两组数字恢复；
另一份新源码副本恢复旧文件并重新编译后重新出现5/2差异。
主源码和共享运行模块保留新版本。基线不是关闭全部投影修正，而是本轮修改前的真实源码。

## 显示链与覆盖方式

1. 从原生保存分支取得8个角色，`B1B94(row,0)` 取得各自的初始普通攻击。
2. F10/F11使用编译后的生产输入适配器，执行原生按键计数、处理、计时、评级与后继技能选择。
   修复旧F10回放固定技能3的覆盖缺口，所请求技能现在贯穿资源查询及选择。
3. 执行对应ATT/EFS加载、条件/异步等待、目标解析、移动/转向、隐藏/显示、CAM加载和镜头推进。
4. 普通攻击和部分F11的伤害来自战斗模型动画的kind9命中命令，而非EFS opcode800。
   实际战斗模型必须用 `B1CB1(row,1)`，不能把探索模型变体0代入。
   `3EA50 → 476A8 → 403 → 401` 与 `EFS800 → 401` 两条路径均执行。
5. 原生受击状态提交、`8C1EB/8E810`结算和`A9EF0`构造弹字，绑定实际受击对象。
6. 每个弹字推进完整原生浮动/销毁生命周期，执行真实FDI/BGR数字选择和绘制提交。
   独立预期坐标来自原生模型可见Draw、ASURA矩阵及驱动投影，不以修正函数自身作坐标预期。

每个脚本持续保留两个存活的耐久测试敌人（受控HP1000000），交替使用可见模型与隐藏模型的
过期缓存。CAM资源逐帧真实推进；每五帧加入一次受控回切，检验画外隐藏后重新入画，
随后恢复源镜头状态，不改变源镜头自身的进度。非有限镜头直接拒绝为有效覆盖。

## 边界及游戏内验收

受击入口和完整弹字生命周期已执行；敌人AI、完整受创动画/死亡状态机不是该显示夹具的目标。
