# 虚拟光标写入与真实鼠标优先级

## Verified：实际输入钩子的受控复现

菜单输入在每次轮询比较引擎鼠标坐标与上次坐标，变化则暂停手柄方向导航，
直到方向回中。旧实现没有记录手柄自己写入的坐标：
`modernGamepadFocusCursor()`移动菜单焦点后，下一次输入将该变化误判为鼠标移动。
右摇杆的Cursor状态机也有同样的观察问题：消费者提交虚拟点后，下一轮又把
该点当成外部输入，连续移动会被自己的前一帧写入阻断。

回归使用现有源形状的标题→输入→实际IAT桥接路径、模拟XInput和原生键盘
保留桩。在主菜单阶段按住十字键Down，聚焦从(400,300)到(400,420)，再轮询：
旧代码实际失败：
`FAIL controller focus write must not masquerade as physical mouse movement`。
不是用手工构造navigation状态绕过输入钩子，也没有执行商业游戏代码。

## 修正

统一的`writeControllerCursor()`仅提交手柄实际写入的整数坐标，并同步两个
观察基线：导航鼠标坐标记录及Cursor的`acknowledgeWrite()`。
方向焦点和右摇杆提交都走这条路径。确认操作不激活初始化、不抹掉真实鼠标
接管状态；只有控制器自己的有效提交调用它。

不同的外部坐标仍被识别为真实鼠标变化，立即暂停导航与右摇杆所有权；
方向/摇杆持续偏转不得抢回，回中后才能重新接管。没有调用SetCursorPos、
SendInput或修改系统鼠标状态，依旧只使用原有游戏虚拟光标字段。
键盘保留、断连重连、窗口前台判断、原事件分发与动作时钟不变。

51项输入/移动综合夹具通过，包括实际IAT桥接的方向接管、聚焦提交、下一轮
保持导航、外部鼠标接管、持续按住阻断、回中恢复及右摇杆连续提交。
该综合夹具连续5次通过；两个右摇杆阶段用20ms宿主等待产生有效轮询间隔，
不将其当作游戏帧率测量。15项独立光标夹具使用明确33ms输入验证相同所有权规则。
20项UI夹具、IAT守卫/键盘保留检查以及229项动作夹具继续通过。
独立源回滚恢复43/10项原行为。437项Python检查通过。
