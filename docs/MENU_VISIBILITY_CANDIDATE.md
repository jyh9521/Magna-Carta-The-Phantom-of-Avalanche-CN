## 实现与守卫

`menu_visibility.cpp` 仅修改标题菜单专属虚表的绘制槽，不修改所有 UI 的通用绘制入口。菜单 owner 的虚表必须匹配标题对象，才读取阶段：0..3（标志/开场）、6（开始）、7（读档过渡）、11（退出过渡）、12（终止）不提交按钮；4（交互）、5（淡入）、8（读档子菜单）、9及未知阶段保持原绘制。空 owner 或非标题 owner 原样转发。

安装检查 PE32/x86、SizeOfImage、原绘制入口32字节、重定位槽指针；launcher 的全文件 SHA 守卫负责磁盘版本。写入使用比较交换且恢复页保护，未知槽拒绝安装；受控回滚只还原自身钩子，第三方改动不会被覆盖。进程结束后内存候选自然撤销。此修复与宽屏无关，应在所有五个验收模式启用。

## 离线回归与游戏验收

`menu_visibility_fixture` 使用自建 PE、菜单/标题对象和自有可执行计数桩，不执行商业函数体。`--baseline-check` 在8种非交互阶段检测到提交按钮并返回1；正常执行验证49项，包括过渡抑制、交互/淡入/读档/未知阶段保留、空/不同 owner 转发、未知槽拒绝和准确回滚，返回0。

真实验收：分别从标题开始新游戏、继续游戏、读取存档，进入探索后返回标题，再退出；检查黑色过渡不再留下四个按钮，同时正常标题、读档子菜单和鼠标点击仍正常。先用 baseline 验收，后再组合模式。游戏验收仍待玩家确认；场景UI、字体灰度与图像资源不因本候选变化。
