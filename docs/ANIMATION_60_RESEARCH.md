# 人物动作 60 FPS 调查

2026-10-13 玩家反馈：监控显示约 60 FPS，但人物动作仍像 30 FPS。本轮已实现骨骼局部姿态插值候选；静态发现、受控夹具与未完成边界分别记录，不把帧率监控当成动作验收。

REA/Ghidra确认Asura `MakeAbsoluteMatrix`（RVA44f0d，Evidence `ev_e533b891ab95926b916f933578c62d29aa489852b7383415d21003c083205cf8`）只进行父矩阵相乘及骨骼子树递归。钩子在同一渲染上下文中计算原版绝对姿态作为恢复副本，再计算插值绝对姿态供本次绘制；绘制结束/异常路径恢复原版绝对姿态。增加约33ms骨骼视觉延迟。世界位移、朝向和摄像机未插值；不宣称完整真60FPS。

## 结论分类

### Verified：首轮呈现补丁未提高动作状态更新频率

首轮 `advanced_display.cpp` 解除了计时器等待分支，保留 33 ms 固定 callback 的比较/消耗，并在驱动呈现处按 60 Hz 节奏返回。它未安装人物姿态/摄像机插值，也未修改动作采样相位。因此玩家反馈与当前实现完全相符：60 次呈现可能重复显示约 30 次动作状态。

### High-confidence deduction：动作包含整数帧推进和同帧事件

同源指令函数 RVA `0x3ea50`：

| 数据/位置 | 静态行为 |
|---|---|
| `this+0x38` | 当前 action 指针 |
| `this+0x40` | 当前整数帧 |
| `action+8` | `framepersample`；源断言字符串明确该名称 |
| `this+0x4e` | 当前帧除采样间隔的商，写入 16 位字段 |
| `action+0x20` | 采样帧事件链；当前帧余数为零时走事件处理 |
| RVA `0x3eb59` | 将当前帧保存到 `this+0x44` |
| RVA `0x3eb65` | 当前帧加 1，回写 `this+0x40` |

该函数不只是生成骨骼矩阵，同时参与事件派发及循环/结束状态。直接把 33 ms 改成 16 ms，或每次呈现额外调用该函数，会改变动作/事件速度；不是本轮修复方案。

### High-confidence deduction：骨骼渲染已有关键帧插值，但输入相位是整数

同源 RVA `0x3b0c0` 的骨骼绘制函数，其虚表静态引用位于 RVA `0xbd9f8`：

- 首个栈参数整数帧先对动作总长 `object->action+4` 求余。
- 再对 `action+8` 求商/余，分别写 `object+0xf8` 与 `object+0xfc`。
- 余数为零时直接复制 64 字节局部骨骼矩阵；非零时调用导入的 `ASRQuatErp1` / `ASRQuatErp2`。
- 插值分子来自整数余数，RVA `0x3b34b` 是 `fild dword ptr [eax+0xfc]`。
- 局部骨骼矩阵数组位于 `object+0x8c`，骨骼计数来自动画资源记录 `+0x14`。
- RVA `0x3b7e3` 附近将局部矩阵传入 `MakeAbsoluteMatrix`，之后参与绘制。

调用链继续闭合：角色绘制函数 RVA `0x3f00d` 在 RVA `0x3f05b` 读取角色 `+0x44` 整数帧，作为首参调用观察对象虚表 `+4`（调用点 RVA `0x3f06d`）。对应骨骼观察对象的虚表 `+4` 指针位于 RVA `0xbd9f8`，值为 `0x5203b0c0`。因此角色更新保存的整数动作帧确实流向骨骼渲染输入。

这给出真正动作插值的候选切入点，而不是再次调整呈现限速。但上述字段用途目前由指令/导入值流推断，尚未通过实际游戏姿态捕获确认。

## 仍未完成的实现条件

动作插值候选已新增为 `src/runtime/motion60.cpp`，本轮仍需守住以下真实动作语义：

1. 使用同一个逻辑计时器的余留相位；不要用独立墙钟猜测每个角色的逻辑相位。
2. 每个角色、动作身份、对象生命周期都应独立缓存，切动作、传送、暂停、加载和销毁时重置。
3. 只对局部姿态/渲染用世界变换做插值，不改动作帧计数、碰撞、事件、战斗判定或存档。
4. 原始零余数分支不能简单强制进入关键帧插值：下一关键帧访问和末帧/循环边界需要验证。
5. 若在 `MakeAbsoluteMatrix` 前插入姿态混合，必须在本次绘制后恢复原始局部矩阵，避免污染下一次逻辑与物理处理。
6. 人物位移、旋转与摄像机都需插值，否则只有骨骼动作平滑而移动/镜头仍跳帧。

## 本轮骨骼动作插值候选

REA 补充：骨骼渲染 Evidence `ev_ba778b5a7bfbfc3380d19d326da11eccb3b30907ac6e32a5eb45c4e2c7c67c54`；角色绘制 `ev_d792a7dd30a58b301dcdfbd41b4bc179253acbf3f30b1dc30764b60868aee8fc`；动作 tick `ev_2efa186ec4077038ddac7a6610d12bc96e5656e9152f8d6044395ff607790a79`。这些是静态反编译，不是游戏执行观察。

候选在骨骼 Render 虚表槽 RVA `0xbd9f8` 建立当前对象/整数帧 TLS 上下文，仅对 MakeAbsoluteMatrix 导入的精确返回点 RVA `0x3b801` 启用局部姿态插值。其他调用直接走原函数。原函数签名是 `void __cdecl(Bone*, unsigned rootIndex, Matrix* inOutPose, Matrix* parent)`；源调用传 rootIndex=0,parent=null。Asura 内部递归计算绝对骨骼矩阵。

候选按对象、action、骨骼树、局部姿态数组、骨骼数和整数帧维护 previous/current。整数帧改变后，在约33ms内插值 previous→current，增加约一个逻辑tick的视觉延迟。旋转采用最短弧四元数归一化线性插值，位移线性插值；非刚性/镜像/非有限矩阵保持当前原样。首帧、动作变更、跳帧、暂停超过250ms及对象状态变化重置缓存，最多128个对象，每个最多512根骨骼。

MakeAbsoluteMatrix 首先计算不修改的 absolute baseline，再对插值后的局部姿态运行同一个原变换。绘制后通过独立 SEH `__finally` 恢复精确 baseline absolute 数组；它不是把局部矩阵错误地留给下一次逻辑。动作tick、帧计数、事件、碰撞、音频保持原样。**世界位移、模型朝向和摄像机未插值，因此不标记全游戏完整真60FPS。**

独立原生夹具 `motion60_fixture` 执行自建 renderer→scoped绝对矩阵hook→original stub 调用，验证实际半步骨骼姿态、旋转中间态、绘制后精确恢复与SEH恢复。PE32映像夹具验证重复安装、重复移除、源前缀/调用点/IAT/尺寸漂移拒绝与精确槽位回滚。结果27项通过；不执行商业引擎，不替代实际动作与游玩验收。
