# 环绕视角：原鼠标移动坐标转换

## Verified：原路径

支持MCAlpha.dll SHA256 `5c701de93af6267b959c49e6927bee525bc0f3c68c8c6f51413515d13809d427`。
REA原6e8fa在6e92c调用02e02读取鼠标局部坐标，再调用0d7bc读取逻辑画布中心。
源点02e02复制f20b0/f20a8并返回输出指针；0d7bc返回f1b48/f1b4c的一半。
原算法将(dx,dy,0)重排为(dx,0,dy)，去掉逆相机的平移，再求朝向。
原actor+bc指向65504，该朝向函数只用X/Y决定方向。

对于列主刚体view，原鼠标地面方向是
`(view[0]*dx + view[2]*dy, view[4]*dx + view[6]*dy)`。
现在用显示视角求目标方向，再解原视角2×2地面基，产生等价的原鼠标坐标。
保留整型取整误差；退化基、非有限值、越界、过期或其他相机不转换。

## 修改边界

只替换6e92c这一个五字节call；调用前后指令、原目标、PE架构和大小均检查。
共享入口仍核对完整源SHA。原getter仍执行，返回指针和cdecl约定不改。
转换仅修改该调用者栈上的返回坐标副本，不写系统光标、UI全局坐标或游戏相机。
原鼠标移动、人物方向与速度调用保留；菜单及其他鼠标读取点不改。
仅世界可控探索状态且存在新鲜的同一相机环绕视角副本时启用。

## 验证

夹具在真实call位置调用自建getter桩；基准返回(500,300)。
旋转后的期望(400,159)在原路径失败，在修改路径通过。
306检查包含三种逻辑分辨率、12个旋转角及不同俯仰、四个方向；
检查原地面射线与显示射线在整型取整误差内一致。
还覆盖原返回指针、全局光标/相机不变、菜单、关闭、过期、身份、退化和未知代码。
独立夹具副本回滚恢复原call和(500,300)，当前模块未回滚。
静态原路径与数学/钩子夹具通过不等同于实机相机或鼠标体验通过。

## 玩家验收

入口 `runtime/Play-camera.cmd`；带手柄为 `runtime/Play-camera-gamepad.cmd`。
F6打开环绕，Ctrl+Alt+小键盘4/6旋转，F7重置。

1. 同场景先不旋转，再旋转后按原鼠标移动操作，检查方向是否跟随显示镜头。
2. 转动不同角度及俯仰后重复；鼠标光标本身不得被移动或跳位。
3. 点菜单和对话按钮，检查命中位置仍正确。
4. F7重置后检查原鼠标行为，以及键盘/手柄方向修复是否保持。
