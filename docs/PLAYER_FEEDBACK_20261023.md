# 战斗输入、伤害定位与长对白调查

## 验证条件

本轮只执行源码检查、Win32自有夹具和Unicorn原始指令回放，不启动游戏。
共享游戏数据、13份存档及增强设置保留，不创建完整游戏副本。
离线通过与真实战斗、声音播放及画面验收分别记录。

支持输入仍为当前共享目录的MCAlpha.dll，SHA-256
`7e8649425217d3b99d52d11c679761a88c57b125c241b331aea5c25e00e3b15e`。

## 60帧连击：消息队列短按丢失

后续调查定位到额外呈现帧取出键盘松开消息、33ms原生轮询只读最终线程状态的机制，
不是原生窗口缩半。真实按下沿现在缓存到下一次战斗采样，保留原有判定、伤害和60Hz动作平滑。
完整原始调用链、输入差分和修正边界见[连击输入修正](COMBO_INPUT_EDGE_REPAIR.md)。

上一轮关闭攻击者插值的兼容候选已撤回；原夹具复用了错误场景虚表`c195c`，
真实构造写入`c1960`。后续作用域验证以真实构造和虚表槽为依据，不再重复旧常量。
后续离线回归与构建记录以`build/combo-root-cause`为准，以下交付记录保留为上一版历史。

## 战斗手柄和一次性连招辅助

原生战斗键盘轮询来自RVA `a0b8d`，返回位置`a0b92`，场景虚表为`c1960`（经构造函数复核）。
确认事件沿GUI键盘分发进入原生战斗监听器`a2f7a`及连击处理`a3681`。
该作用域下A映射原生Space、B映射Esc，方向键交给原生界面，
不再让通用虚拟菜单焦点屏蔽战斗方向输入；菜单与探索映射分别保留。

F10或已启用手柄的右摇杆按下请求一次连招。辅助读取原生连击阶段、计数、
逻辑tick和配置`0x23/0x24`，只在原有判定窗内发送Space边沿。
不修改伤害、角色属性、存档或判定窗口。普通确认键保持物理输入优先。
每次请求有独立结束条件，离开战斗、失焦及手柄请求断连时取消。
手柄关闭时F10仍可用，不加载XInput、不改变探索按键。

辅助不是固定毫秒宏，也不自动选择所有战斗菜单。
先选择普通攻击及目标，释放普通确认键，再按一次辅助键；
战斗之外不产生确认事件。实体手柄及完整战斗成功率仍待手动验收。

## 伤害数字

原D3D驱动未实现所需光栅位置/有效标志查询，原生调用者可能读到未初始化坐标。
三处精确调用点补充当前矩阵投影，保留原生Y翻转、浮动与裁剪。
未知驱动透传，普通和宽屏画布独立验证。
完整根因、原始指令、红绿与撤回证据见
[伤害投影修正](DAMAGE_PROJECTION_REPAIR.md)。

## 长对白自动推进：保留原声尾段

**已验证的机制缺口**：对白状态3的自动倒计时归零后，原生结束分支不检查语音。
构造函数虽然按语音帧长计算揭字速度，末尾又固定写入速度5；
较早显示完的文字可以在原声结束之前进入状态6，由脚本销毁对白并继续剧情。
原生结束指令的受控回放在仍有400tick原声时立即退出，等待守卫后在第400tick退出，
手动确认仍能在第10tick立刻推进。

修正只阻止自动到期：语音对象、源文本、声道及stream句柄匹配、原生Miles播放状态仍活动时，
临时保留等待状态。播放结束、对象失效、声道复用或有界时限到达即放行。
无声对白和手动等待模式不增加固定延迟，按键确认仍走原生路径。

最长五条实际译文经完整原生滚动重放，逐字节收集标签均完整；
这排除所测文本的滚动丢字，不证明所有剧情脚本没有其它问题。
语音尾段缺口与玩家普遍长对白反馈高度吻合，但实际声音及所报漏段仍待手动复验。
声音对象与精确调用桥、原生播放状态及回滚细节见
[自动对白与原声状态](DIALOGUE_AUTOPLAY_VOICE.md)。

## 共享模块更新与撤回

所有现有角色模块以同一源版本构建，保留原有功能开关和入口。
更新器先验证整份运行文件清单，再原子更新12份自有DLL和运行清单，
保留原始摘要与小型备份；存档、游戏资源和可编辑增强设置不进入替换集合。
输入漂移、备份漂移及未知路径整批拒绝，部分写入失败恢复原文件。

```powershell
cmake --build build/native --config Release --parallel 4
python tools/update_runtime_modules.py apply --runtime runtime --module build/native/Release/workspace_profile.dll --record build/NEW-module-update
python tools/update_runtime_modules.py rollback --record build/NEW-module-update
```

独立小型运行夹具验证整批撤回；活动共享目录保留候选。
玩家小更新复用已有PowerShell增量更新器，不要求安装Python：

```powershell
python tools/build_text_runtime_update.py --runtime runtime --record build/NEW-module-update --output dist/NEW-feedback-update.zip
```

构建产物和详细原始输出位于本机`build/player-feedback-20261023`，不提交完整游戏文件。

## 交付验证

完整Python回归779项，1项依条件跳过；46组自有离线检查得到预期结果。
其中旧源输入、旧源对白回归失败，新源通过，独立旧源恢复后再次失败。
攻击者姿态兼容候选另有旧源／新源／旧源回滚的三态比较。
12份自有运行模块及清单在小型隔离运行夹具中整批恢复原摘要，活动共享目录保留新版。
实际PowerShell玩家更新器的Verify／Install／CheckInstalled／Rollback四态均通过，
没有复制商业游戏数据；设置和自有存档哨兵始终保持原字节。

小更新包为`dist/MagnaCarta-feedback-update-20261023.zip`，适用于同一原始运行清单的
2026-10-22统一测试包。ZIP不含完整商业游戏文件、存档或可编辑增强设置。
解压后使用`Update.cmd -Action Verify -Runtime 已安装共享目录`核对，
再以`-Action Install`安装；`-Action Rollback`恢复该小更新前的自有模块。
未知或混合版本先整批拒绝，不覆盖后续修改。

人工复验仍由测试者另行启动原`runtime/Play.cmd`：同存档对照30/60帧普通攻击、
战斗方向／A／B、不同敌人头顶伤害数字，长语音无人输入完整播完后推进，
以及F10／R3初次触发、半途接管、失焦／断连取消。
不将离线候选与小更新器通过写成五项现场反馈全部验收。
