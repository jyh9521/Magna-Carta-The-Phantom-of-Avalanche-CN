# 动作循环边界绘制缓存修复

## Verified：源版本及原更新

支持 MCAlpha.dll SHA256 `5c701de93af6267b959c49e6927bee525bc0f3c68c8c6f51413515d13809d427`。
REA 静态反编译 `0x5203ea50` 的原动作更新保存当前帧到 actor+44，递增 actor+40；
actor+3c 为 1 且帧达到 action+4 时，将 actor+40 设为 0。
动作事件仍由原更新执行，补丁没有增加任何动作更新调用。

## Verified：缓存缺陷与回归

旧 absoluteHook 把除同帧、frame+1 外的所有帧变化当作不连续。
循环末帧→0 因而同时重置骨骼、局部变换和组合变换插值缓存。
夹具将四帧动作从 3→0 回放，旧代码实际返回第一帧姿态，
断言 `native loop wrap begins at previous last pose, not first-frame snap` 失败。

现在仅同一动作、相同总长度、相邻原逻辑阶段允许 length-1→0 连续插值；
新增 Cache.clipLength，并保留倒退、跨帧、时钟变化、动作资源变化等重置。
相邻帧比较使用 64 位整数，避免有符号 frame+1 溢出。
原帧、事件、速度与写回姿态不变。过渡仍保持原有一逻辑步绘制延迟。
77 项原生夹具通过，其中包含新循环中间态、跳帧、逆序、长度变化检查；
独立源回滚恢复此前 68 项通过。432 项 Python 检查通过。

## High-confidence deduction / 未验收

该缓存缺陷会在循环边界产生绘制跳变，但没有实机证据证明该缺陷是用户抽搐的唯一原因。
绘制钩子未读取 actor 的循环标志：同动作末帧→0 的强制重新播放与正常循环
在此位置不可区分。选择维持连续绘制，不更改逻辑或事件；需关注重新播放是否出现拖影。

## 玩家验收

入口 `runtime/Play-motion.cmd`，对照 `runtime/Play-baseline.cmd`，复用同一份数据。
1. 同存档待机至少 30 秒，观察重复动作每次回到起点是否抽动。
2. 连续走动、转身、停止各 10 秒；比较衣摆、四肢和人物位置。
3. 切换动作、换区域、暂停恢复，检查跳变或拖影；观察事件和移动速度是否变化。
4. 如果仍抽搐，注明待机/行走/切换动作中哪种发生，是否规律重复。
