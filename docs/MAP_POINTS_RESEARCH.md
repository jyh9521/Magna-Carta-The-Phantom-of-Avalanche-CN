# 地图物件与领取状态：静态证据

当前操作见 [F9 地图测试版](MINIMAP_F9_TEST.md)，出口触发点另见 [出口点资料](MAP_EXIT_POINTS.md)。本页记录物件分类和领取状态，不把静态分析称作游戏内验收。

## Verified：目标与坐标对象

源文件为支持版本 `MCAlpha.dll`，SHA-256：

```text
7e8649425217d3b99d52d11c679761a88c57b125c241b331aea5c25e00e3b15e
```

PE32 / x86，时间戳 `0x3ed73966`，`SizeOfImage=0x10b000`。下列位置均为相对模块基址的 RVA；静态分析使用 REA / Ghidra 和独立 x86 指令解码核对，不执行原游戏。

`0x68996` 的场景加载分支把 Field object kind `3` 实例化为 `FNPC`（运行时类型 `0x16a`），把 kind `6/7` 实例化为 `FBOXOBJ`（`0x168`）。活动对象链表位于 `scene+0x1594`，头节点为 `scene+0x159c`；节点 `+0` 是对象，`+4` 是下一节点。地图坐标仍取活动对象 `+0x48/+0x4c/+0x50`，不是静态 Field 坐标缓存。

对象 `+0xd4` 只表示禁用状态。函数 `0x4ca82` 检查该字段是否非零；已经打开的箱体仍可保留在活动对象链表，因此此字段不能替代领取进度。

## Verified：唯一对象键与记录布局

| 字段 | 位置 / 类型 | 依据 |
|---|---|---|
| 当前 Field ID | `scene+0x10cc`, int32 | 嵌入的 FieldInfo 首字段，不是指针 |
| 当前地图资源 ID | `scene+0x10d0`, int32 | 加载器 `0x68996` |
| object 记录数 | `scene+0x1514`, int32 | 加载器、交互循环 |
| object 记录数组 | `scene+0x1518`, pointer | 内存步长 `0x48`，与文件记录 `0x38` 区分 |
| 记录主键 | `record+0`, int32 | 构造器 `0x63450` 写入 live object `+0xf0` |
| 记录种类 | `record+8`, int32 | 交互函数 `0x6bbbb` 分派 |
| 奖励物品 ID | `record+0x24`, int16 | 箱体、NPC 赠物调用 `0x71520` |
| 全局开关索引 | `record+0x26`, int16 | 符号扩展后索引 int32 数组 |
| 钥匙物品 ID | kind 7 的 `record+0x28`, int16 | `0x71670` 检查持有，`0x715e0` 移除 |

`0x6f9a3` 按 live object `+0xf0` 查找对象。观察器反向匹配记录主键，要求匹配唯一；重复键、类型不符或缺失记录返回 `Unknown`，不根据数组顺序猜测。

## Verified：开关数组与边界

`*(engine+0xf2304)` 是全局开关管理器，其虚表 RVA 为 `0xbe774`。

- `manager+0x24`：`int32* m_pSwitch`。
- `manager+0x28`：开关数量，而非 `manager+0x20`。
- `0x4a714` 按数量分配 `count*4` 字节；`0x4a91e` 清零；`0x4a96b` 释放并清零指针及数量。
- 启动路径 `0x5fc1a` 传入 `0x7d0`，即 2000 个开关。
- 原交互路径对 `record+0x26` 使用有符号 16 位读取。观察器额外要求 `0 <= index < count <= 2000`；负索引不解引用。

只读 helper 同时检查 PE 布局、scene 虚表 `0xc12bc`、管理器虚表、完整记录内存区可读性和最多 4096 条记录。4096 是观察器工作上限，不是已证明的游戏格式上限。可读页检查之外，读取异常也返回 `Unknown`。完整源文件摘要由部署与外层版本锁定负责，PE 字段检查不冒充完整摘要认证。

## Verified：箱体与 NPC 奖励状态

| 记录种类 | 仍可领取 / 处理中的状态 | 已消耗状态 | 其他情况 |
|---|---|---|---|
| kind 6 普通箱 | `0` 尚未触发；`1` 开箱动作中 | `2` 已执行物品授予分支；`3` 提示结束 | 未知值返回 `Unknown` |
| kind 7 钥匙箱 | `0/1` 同上；`4` 缺钥匙提示中，提示结束回 `0` | `2/3` 同上 | `4` 不是领取完成 |
| kind 3 NPC 赠物 | `item != -1` 且对应开关为 `0` | 赠物后开关写 `1` | `item == -1` 是无奖励哨兵 |

普通箱授予调用位于 `0x6c080`，写状态 2 位于 `0x6c1e1` 附近；钥匙箱授予调用位于 `0x6c8ca`，写状态 2 位于 `0x6ca84` 附近。NPC 赠物调用为 `0x6d79d`，随后开关写 1。`0x71520` 搜索 1024 个背包槽并调用 `0x71580` 写入；背包满时返回 0，而上述交互路径仍推进开关。因此地图的“已消耗”描述原生交互状态，不保证背包实际增加物品。

加载器对 kind 6/7 的开关值大于 1 时设置已打开动作并归一为状态 3。地图每帧读取当前值，不自行修改、保存或永久缓存开关；缺钥匙临时状态 4 按当前交互分支处理。

NPC 绿点是否显示取决于活动对象和禁用状态，不因奖励已经领完而消失；奖励可用仅作额外标记。未确认领取状态的箱体只能作为空心位置标记，不能标成“仍可收集”。

## 已检查范围与未验证部分

572 份可解析 Field 静态前缀包含 69 条 kind 6、22 条 kind 7、53 条 kind 3，其中 28 条 NPC 记录带非 `-1` 奖励物品；25 份前缀仍被既有解析器拒绝。通过样本的箱体开关索引均非负。此统计不是当前存档的活动物件数量。

kind 4 在已核加载分支仅把坐标写入 `scene+0x1714`，不进入已核原生物品授予分支；kind 5 未在这批通过的前缀中出现。`0x71520` 的其他直接调用还包括装备菜单的物品返还操作，不构成地面拾取位置证据。

**未验证：** 独立地面亮点、脚本授予或其他交互物件的可靠类型及领取状态。不得把未知 kind、任意有位置的对象或所有脚本物品授予画成可收集物。NPC 奖励标记只表示当前记录中尚未领取的赠物，不表示对话或剧情前置条件全部满足。

## 离线验证接口

`src/runtime/map_collectibles.h` 提供 `classifyMapCollectible(engine, scene, objectId, nativeType)`，返回 `ContainerAvailable / ContainerConsumed / NpcReward / NoReward / Unknown`。调用方负责活动世界、对象身份、禁用状态及实时坐标检查。

自有最小测试目标 `map_collectibles_fixture` 覆盖普通箱、钥匙箱缺钥匙提示、NPC 赠物、负索引、动态数量上界、重复键、PE/虚表漂移、跨页不可读内存及读取前后字节不变；该目标不启动窗口或原游戏。实际合成、地图对齐和存档领取前后验收仍由人工完成。

本地完整摘要及短指令片段保存在 `runtime/maintenance/minimap-f9-20261025/collectible-source-evidence.json`；不提交完整游戏二进制或原始资源。
