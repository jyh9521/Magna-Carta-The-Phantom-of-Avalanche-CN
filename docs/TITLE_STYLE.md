# 标题按钮状态样式

## 已核原生字段

MCAlpha.dll SHA256 `5c701de93af6267b959c49e6927bee525bc0f3c68c8c6f51413515d13809d427`；
Asura.dll SHA256 `f81e7c458d43b77210311499b39b9be2c4895e3a3b356d2e848b6e84210d2557`。
原按钮构造 `56850` 使用vtable `bee80`，焦点/按下标志在+198/+19c，
原 `57003/5707d` 设置/清除焦点。
标题四项ID为16c–16f，listener指向标题GUI（c2340），GUI+1a8指向标题场景（c22f0）。
样式仅在标题场景阶段4处理这四项；读取存档窗口、其他按钮、开场和背景不处理。

原BGR构造422f0使用bdb9c，顶点地址为对象+124；原42503通过IAT bd01c提交
格式0x102、原始四边形（primitive5、count4）。收集对应按钮绘制树中的BGR顶点，
不按纹理编号全局着色，避免共享背景/其他UI纹理跟着变色。

## 真正生效的颜色状态（Verified）

Asura导出 `ASRRegRender`（RVA51a01）具有14个cdecl参数，
将RGBA全局状态RVA3e2800复制到绘制队列记录+0xd80（索引360–363）。
队列执行 `50b89` 在0x102路径用这一份RGBA调用驱动颜色接口+b0。
看似颜色的第8个整数参数在这条路径没有用于着色；最初的浅层测试方案已弃用，未发布。

新钩子仅在指定按钮的匹配顶点提交时临时乘RGB，保持A不变。
原提交复制状态后，finally逐字节恢复16字节RGBA；异常路径同样恢复。
源ARGB整数参数及其他13个参数保持不变。没有修改图像、原文、字体或资源文件。

## 样式与验证

普通RGB：170/166/158（柔和灰白）；焦点：255/189/102（琥珀）；
按下：255/143/53（橙）；禁用：112/110/104。
颜色是乘原颜色，原透明度和淡入淡出保留；不是强制覆盖Alpha。

独立原生夹具基准确认原白色。`--baseline-check`期望普通色时失败；
启用版57检查通过：排队颜色、四项ID、焦点/按下/禁用、Alpha、背景、
开场/读档排除、SEH上下文恢复、两个钩子精确回滚、未知调用位置拒绝。
回滚在另一个夹具可执行副本运行，恢复原白色和原槽，当前运行模块不回滚。
实机菜单外观未验收，未启动游戏。

## 启动与玩家验收

`runtime/Play.cmd`现使用新样式；手柄和动作入口同样使用新样式。
`runtime/Play-title-original.cmd`设置`MC_TITLE_STYLE=0`，以相同配置显示原按钮样式。
其他特性开关及默认设置未改；所有入口复用`runtime/data`。

1. 主菜单四项普通状态应不再呈亮白色；背景、标题、版本号保持原色。
2. 鼠标逐个移过四项：选中变琥珀色；离开回灰白，不能遗留多项选中。
3. 按下按钮显示橙色；切入读档窗口后，该窗口内容保持原样。
4. 开始游戏、返回标题、退出时，检查先前修复的按钮残留没有回退。
5. 手柄方向导航也应采用同一焦点反馈。实际效果由玩家确认，不以夹具颜色代替画面验收。

仍待最终验收：完整60FPS、全部手柄状态、视角移动与地图实用性。
