# 鼠标控件与原生方向键控件的准入差异（2026-10-15）

## Verified

支持版本 MCAlpha.dll SHA256 `5c701de93af6267b959c49e6927bee525bc0f3c68c8c6f51413515d13809d427`。

原始键盘分发 `55134` 调用虚表 `+1d0 → 565d2`：可见、启用、无独占窗口时仅 `+164=0` 接受键盘；独占窗口存在时仅精确窗口对象接受，局部模式不再限制。原鼠标准入 `+1dc → 5663f` 则允许无独占时模式 0/1。两者不是同一谓词。全部 21 个受支持类的键盘准入槽均核对为 `565d2`。

REA：键盘分发 ev_ec915579162132a156003dc0ad0afba472b004656ae28c9691d4595d74fd02c8；键盘准入 ev_96991535e31649f560a68714ee35f8f657b86871e76a55087681f9792db148f1；空闲计数 ev_efc0cf54bac778f17ebdd34866afa71f45ff558a6436350b0d3b978c2961f4f3。

旧收集器把“有自定义方向方法、鼠标可点击、光标位于内部”当作原生方向消费者，漏了键盘准入。模式 1 控件可能因此停掉虚拟导航，但原键盘又拒绝处理，造成方向焦点停滞。旧生产源加新回归实际失败：`FAIL mouse-only custom control must not take native keyboard ownership and trap virtual navigation`。

现在鼠标与键盘共用基础可见/启用/独占规则，但分别判断模式；只有原键盘准入也通过，才将方向交给原生控件。模式 1 继续虚拟焦点导航，模式 0 自定义方向控件保留原处理。安装/卸载新增 21 个键盘准入槽守卫，未知槽在任何写入前拒绝。没有改变按键映射或菜单点击条件。

此前夹具的一项“原生方向消费者”也错误采用模式 1，现改用模式 0；模式 1 拒绝与模式 0 接管分别测试，不再用自有桩绕过原始准入规则。
